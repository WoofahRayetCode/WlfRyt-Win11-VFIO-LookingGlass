-----------------------------------

  EFI/System → MSR → C: (~255GB) → Recovery (~730–854MB) → Unallocated (~768GB)

Recovery sat BETWEEN C: and free space, so Extend was blocked.

Guest fix performed:
  1. reagentc /disable  (reported already disabled)
  2. diskpart: select disk 0 → select partition 4 (Recovery ~854MB)
     → gpt attributes cleared if needed → delete partition override
     IMPORTANT: Partition 3 was C: (Primary ~254GB). Deleting 3 fails with
     “boot/system/pagefile…” — that error meant wrong partition selected.
  3. Extended C: into free space — SUCCESS

WinRE recovery partition is gone; fine for gaming VM. Optional later:
recreate small Recovery at end of disk + reagentc /enable.

F) Network performance (measured / discussed; NO NIC change made)
----------------------------------------------------------------
Current guest path:
  • NIC model: e1000e (Intel 82574L lookalike)
  • Mode: libvirt NAT → network 'default' / virbr0
  • MAC kept: ac:f4:66:28:f0:3d
  • Guest DHCP lease seen as 192.168.122.29 (Win11VM)
  • Host uplink: WiFi wlan0 (eno1 ethernet down during checks)
  • No libvirt <bandwidth> cap on the NIC

Findings:
  • Host WiFi PHY looked excellent (~2.4 / 1.9 Gbps link, ~-47 dBm).
  • One public 100MB download sample on host was only ~118 Mbps — that
    sample was server-limited, NOT the real host ceiling.
  • User reports host can reach upwards of ~1.5 Gbps.
  • Therefore the Windows VM is likely leaving speed on the table:
      e1000e is emulated ~1 GbE and usually cannot approach multi-gig.
  • NAT adds some overhead, but e1000e is the main guest-side ceiling.
  • QEMU guest agent is NOT configured, so in-guest speed tests must be
    run manually inside Windows.

BattlEye vs speed (decision recorded):
  • Keep e1000e for now if GTA Online / BattlEye still matters.
  • VirtIO NIC = biggest guest speed win, but higher BattlEye risk
    (Red Hat VirtIO Ethernet fingerprint — same class of tell removed
    from the system disk).
  • Host Ethernet alone helps WiFi flakiness; it does NOT remove the
    e1000e guest cap.
  • NO network XML change was applied after this discussion.

If chasing speed later (accept BattlEye risk):
  1. Backup XML
  2. Change interface model e1000e → virtio (optionally vhost)
  3. Ensure VirtIO net drivers present in guest
  4. Easy rollback to e1000e + same MAC
